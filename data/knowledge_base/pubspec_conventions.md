# pubspec.yaml Conventions

Every Flutter app has a `pubspec.yaml` at its root with this structure.

## Template

```yaml
name: my_app
description: Generated by SDLC Agent.
publish_to: "none"
version: 0.1.0+1

environment:
  sdk: ">=3.0.0 <4.0.0"
  flutter: ">=3.16.0"

dependencies:
  flutter:
    sdk: flutter
  cupertino_icons: ^1.0.6

  # State management
  flutter_bloc: ^8.1.0
  equatable: ^2.0.5

  # Navigation
  go_router: ^13.0.0

  # Local storage
  hive: ^2.2.0
  hive_flutter: ^1.1.0
  path_provider: ^2.1.0
  shared_preferences: ^2.2.0

  # Networking
  http: ^1.1.0

  # Formatting
  intl: ^0.19.0

  # Images
  cached_network_image: ^3.3.0
  image_picker: ^1.0.0

dev_dependencies:
  flutter_test:
    sdk: flutter
  flutter_lints: ^3.0.0

flutter:
  uses-material-design: true
  assets:
    - assets/images/
    - assets/icons/
```

## Rules

- Keep `publish_to: "none"` — these are private apps, never published to pub.dev.
- Pin Dart SDK to `>=3.0.0 <4.0.0` so null safety works.
- Always include `cupertino_icons` — Material theme fallback on iOS uses them.
- Group dependencies by category with comments — improves diff reviewability.
- Only add a package when you actually use it; unused deps inflate build size.
- When generating a pubspec, use version bounds `^x.y.z`, not `any` — `any` causes drift across installs.

## Adding a new package

1. Add to `dependencies:` in the right category.
2. Run `flutter pub get` to resolve and lock.
3. Import in the `.dart` file: `import 'package:<name>/<name>.dart'`.
